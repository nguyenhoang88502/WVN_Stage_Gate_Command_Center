BUG 1 — Gate approval "Cancel" triggers auto-approval
============================================================

Location: function gateActions(project, proc, step, g, redraw), the `ap.onclick`
handler (the "Approve step N" button), currently reads:

  ap.onclick = async () => {
    const who = requireName(); if (!who) return;
    const note = prompt('Comment (optional):', '') || '';
    await API.action('lb_approvals', {
      project_id: project.project_id, step_key: sk, deliverable_id: '', approved_by: who, approved_utc: new Date().toISOString(),
      approval_type: proc === 'NPI' ? 'Evidence-Based' : 'Milestone', evidence_count: g.ev.length, comments: note
    });
    await API.action('lb_gates', {
      project_id: project.project_id, process: proc, step_key: sk, step_num: step.step_id, step_name: step.step_name,
      status: 'Approved', approved_by: who, approved_utc: new Date().toISOString(),
      evidence_cited: g.ev.map(x => x.code + '=' + x.ev.level).join('; '), updated_utc: new Date().toISOString()
    }, { upsertKeys: ['project_id', 'step_key'], audit: { user: who, action: 'Approve_Gate', projectId: project.project_id, objType: 'Gate', objId: sk, from: 'Open', to: 'Approved', detail: note } });
    await redraw();
  };

ROOT CAUSE: the browser's native `prompt()` returns `null` when the user clicks
Cancel (or presses Escape), and returns `''` (empty string) when the user clicks
OK with an empty textbox. The code does `prompt(...) || ''`, which collapses
BOTH cases to `''` and then falls straight through into approving the gate
regardless of whether the user clicked OK or Cancel. Clicking Cancel on this
prompt currently still signs/approves the gate — that is the bug.

FIX: distinguish `null` (Cancel/Escape) from `''` (OK with no comment typed).
On Cancel, return immediately WITHOUT calling `API.action('lb_approvals', ...)`
or `API.action('lb_gates', ...)`, and without calling `redraw()` — leave the
gate exactly as it was, and leave the button re-clickable (do not disable it,
do not leave any stray DOM state behind; nothing else in this handler holds
state across calls so a plain early `return` is sufficient).

Example of the corrected shape (adapt to match the exact surrounding code):

  ap.onclick = async () => {
    const who = requireName(); if (!who) return;
    const noteRaw = prompt('Comment (optional):', '');
    if (noteRaw === null) return; // user clicked Cancel / pressed Escape — abort, do not approve
    const note = noteRaw;
    await API.action('lb_approvals', { ... });
    await API.action('lb_gates', { ... }, { ... });
    await redraw();
  };

Keep everything else in the handler (the two API.action calls, their payloads,
the audit block) byte-for-byte identical — only the Cancel-detection logic
changes.
